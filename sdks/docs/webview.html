WebView / Redirect Integration

Simplest integration — redirect users to a CIP-hosted verification page. No SDK required.

Overview

The WebView/Redirect integration is the fastest way to add KYC to your platform. Your backend creates a session, you redirect the user to the CIP-hosted verification page, and CIP handles the entire UI. When done, the user is redirected back to your callback URL with the result.

Best for

  • Rapid integration — no frontend code required
  • Platforms that want CIP to handle the entire KYC UI
  • Mobile apps using WebView or in-app browser
  • Server-rendered applications (PHP, Django, Rails, etc.)

Step-by-step

  1. Create a KYC session — Your backend calls POST /api/v1/kyc-sessions with the customer's details and callback URLs. CIP returns a session_id, web_url, and mobile_url.
  2. Redirect the user — Send the user to the web_url (for browsers) or mobile_url (for mobile deep links). The CIP-hosted page handles document capture, selfie, and liveness.
  3. User completes verification — The user follows on-screen instructions: capture CNIC front/back, take a selfie, and (for advanced verification) complete liveness checks.
  4. CIP redirects back — After completion, CIP redirects the user to your web_callback_url with query parameters: ?session_id=xxx&status=approved
  5. Receive webhook — CIP sends a webhook to your configured URL with the full session result, including KYC status, risk tier, and customer ID.

API Reference

Create Session

POST /api/v1/kyc-sessions

Creates a new KYC session. Requires JWT authentication (your VASP API key).

Code Examples

Backend: Create Session (Node.js)

JavaScript 
const createKycSession = async (userId, userName, userCnic) => {
  const response = await fetch('https://api.cip.pk/api/v1/kyc-sessions', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${process.env.CIP_JWT_TOKEN}`,
    },
    body: JSON.stringify({
      external_ref: userId,
      customer_name: userName,
      customer_cnic: userCnic,
      web_callback_url: 'https://yourapp.com/kyc/callback',
      mobile_callback_url: 'yourapp://kyc/callback',
    }),
  });

  const data = await response.json();
  return data; // { session_id, web_url, mobile_url, ... }
};

class KycViewController: UIViewController, WKNavigationDelegate {

        super.viewDidLoad()
        webView = WKWebView(frame: view.bounds)

            webView.load(URLRequest(url: url))
        }

    func webView(_ webView: WKWebView,
                 decidePolicyFor navigationAction: WKNavigationAction,
                 decisionHandler: @escaping (WKNavigationActionPolicy) -> Void) {
        if let url = navigationAction.request.url,
           url.host == "yourapp.com",
           url.path == "/kyc/callback" {
            // Extract session_id and status from query params
            handleKycComplete(url: url)
            decisionHandler(.cancel)
            return
        }
        decisionHandler(.allow)
    }
}

Mobile: Kotlin (Android WebView)

Kotlin 
class KycActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        val webView = WebView(this)
        setContentView(webView)

        webView.settings.javaScriptEnabled = true
        webView.settings.mediaPlaybackRequiresUserGesture = false

        webView.webViewClient = object : WebViewClient() {
            override fun shouldOverrideUrlLoading(
                view: WebView, request: WebResourceRequest
            ): Boolean {
                val url = request.url
                if (url.host == "yourapp.com" &&
                    url.path == "/kyc/callback") {
                    val status = url.getQueryParameter("status")
                    val sessionId = url.getQueryParameter("session_id")
                    handleKycResult(sessionId, status)
                    return true
                }
                return false
            }
        }

        webView.loadUrl(sessionUrl)
    }
}

Callback URL Handler

Node.js (Express) 
// Handle the redirect callback from CIP
app.get('/kyc/callback', async (req, res) => {
  const { session_id, status } = req.query;

  // Always verify status from CIP API (don't trust query params alone)
  const session = await fetch(
    `https://api.cip.pk/api/v1/kyc-sessions/${session_id}`,
    { headers: { 'Authorization': `Bearer ${CIP_TOKEN}` } }
  ).then(r => r.json());

  if (session.kyc_status === 'approved') {
    // Update your user record
    await markUserVerified(session.customer_id);
    res.redirect('/dashboard?kyc=success');
  } else {
    res.redirect('/kyc-failed?reason=' + session.kyc_status);
  }
});

Configuration

Callback URLs

ParameterUsageExample
web_callback_urlBrowser redirect after completionhttps://yourapp.com/kyc/callback
mobile_callback_urlMobile deep link redirectyourapp://kyc/callback

CIP appends ?session_id=xxx&status=yyy to your callback URL.

Verification Level

The verification level is configured at the tenant level in the CIP dashboard under Settings > KYC. When liveness_required is enabled, all sessions use advanced verification (liveness + document-in-hand).

Customer Data Fields

Pre-filling customer data reduces verification time and improves accuracy:

  • customer_name — Matched against CNIC OCR data
  • customer_cnic — Used for NADRA verification. If provided, the OCR-extracted CNIC is cross-referenced.
  • customer_dob — Matched against document date of birth
  • external_ref — Your internal user ID. Use this to link CIP customers to your user database. Included in webhook payloads.

Webhook Events

EventTriggerData
kyc.session.completedSession finished (any result)session_id, status, kyc_status, risk_tier, customer_id, external_ref
kyc.session.approvedIdentity verifiedsession_id, customer_id, risk_tier, external_ref
kyc.session.rejectedVerification failedsession_id, kyc_status, rejection_reason, external_ref
kyc.session.expiredSession timed outsession_id, external_ref
test.pingManual test from dashboardmessage, tenantId

Important

Always verify the webhook signature and confirm session status via the API before taking action. Do not rely solely on webhook data for critical decisions like account activation.
