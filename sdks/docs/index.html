Prerequisites

Before integrating, make sure you have the following:

1. CIP Tenant Account

  • Apply for a CIP account at app.cip.pk/apply
  • Your application will be reviewed within 2-3 business days
  • Once approved, you will receive dashboard access

2. API Key

  • Generate an API key from Settings > API Keys in the CIP dashboard
  • Keys are prefixed with cip_live_
  • Store securely — the key is shown only once
  • Only MLRO or Compliance Officer roles can generate keys

3. Session Creation

  • All KYC flows start by creating a session from your backend
  • POST /api/v1/kyc-sessions returns a session_id
  • Pass the session_id to your frontend (SDK or redirect URL)
  • Sessions expire after 30 minutes of inactivity

Verification Levels

  • Basic — Document capture (front + back) and selfie with face matching. Suitable for CDD (Customer Due Diligence).
  • Advanced — Everything in basic, plus liveness detection (blink + head turn) and document-in-hand photo. Required for EDD (Enhanced Due Diligence) and higher-risk customers.

Session Statuses

  • pending — Session created, waiting for user to begin
  • in_progress — User has started verification
  • completed — All steps done, result determined
  • expired — Session timed out

KYC Result Statuses

  • approved — Identity verified successfully. Customer created in CIP.
  • rejected — Verification failed (document mismatch, liveness fail, etc.)
  • pending — Under manual review by CIP or your compliance team

Webhook Notifications

CIP sends real-time webhook notifications to your configured URL when KYC session status changes. Configure your webhook URL in Settings > Webhooks.

Webhook events include:

  • kyc.session.completed — Session finished, result available
  • kyc.session.approved — Customer identity verified
  • kyc.session.rejected — Verification failed
  • kyc.session.expired — Session timed out
  • screening.match_found — Sanctions match detected
  • wallet.risk_changed — Wallet risk score updated
