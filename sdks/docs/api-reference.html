API Reference

Complete REST API documentation for the CIP Compliance Infrastructure Platform.

Authentication

CIP uses two authentication methods:

JWT Bearer Token (Authenticated Endpoints)

For VASP backend-to-CIP communication. Obtain a JWT by authenticating with the CIP auth endpoint using your credentials.

HTTP Header 
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

API Key (SDK Endpoints)

For SDK-to-CIP communication. The SDK sends your API key with each request.

HTTP Header 
X-API-Key: cip_live_your_api_key_here

Session-Based (Public Endpoints)

Public endpoints like /verify, /process-frame, and /complete-step use the session ID itself as authentication. These are called by the hosted verification page and SDKs.

Base URL

All endpoints are relative to: https://api.cip.pk/api/v1
Sandbox: https://sandbox.api.cip.pk/api/v1

KYC Sessions

POST /kyc-sessions JWT Required

Create a new KYC verification session. Returns session ID and redirect URLs for the hosted verification page.

Request Body

FieldTypeRequiredDescription
external_refstring (max 255)NoYour internal user/customer ID
customer_namestring (max 255)NoPre-fill customer name
customer_cnicstring (max 20)NoCNIC number for NADRA verification
customer_phonestring (max 20)NoPhone number
customer_dobstring (max 10)NoDate of birth (YYYY-MM-DD)
customer_nationalitystring (max 100)NoNationality
web_callback_urlstring (max 1024)NoBrowser redirect URL after completion
mobile_callback_urlstring (max 1024)NoMobile deep link callback

Response (201 Created)

JSON 
{
  "session_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "status": "pending",
  "current_step": "upload",
  "kyc_status": null,
  "risk_tier": null,
  "customer_id": null,
  "liveness_required": false,
  "web_url": "https://app.cip.pk/verify/a1b2c3d4-...",
  "mobile_url": "cip://verify/a1b2c3d4-...",
  "expires_at": "2026-03-31T15:30:00Z",
  "completed_at": null,
  "created_at": "2026-03-31T15:00:00Z"
}

Try it

cURL 
curl -X POST https://api.cip.pk/api/v1/kyc-sessions \
  -H "Authorization: Bearer YOUR_JWT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "external_ref": "user-12345",
    "customer_name": "Ahmed Khan",
    "customer_cnic": "42101-1234567-8",
    "web_callback_url": "https://yourapp.com/kyc/callback"
  }'

Check the current status of a KYC session. Tenant-isolated: you can only access sessions belonging to your tenant.

POST /kyc-sessions/{session_id}/process-frame Public

Process a single verification frame through the ML engine. Called by the hosted page or SDK when the user captures a photo. Returns OCR data, face match score, quality assessment, and pass/fail.

Request (multipart/form-data)

FieldTypeRequiredDescription
stepstringYesOne of: document_front, document_back, selfie, liveness, document_in_hand
filebinaryYesImage file (JPEG/PNG, max 10MB)

Response (200 OK)

JSON 
{
  "step": "document_front",
  "passed": true,
  "data": {
    "ocrName": "AHMED KHAN",
    "ocrCnic": "42101-1234567-8",
    "ocrDob": "1995-03-15",
    "ocrGender": "M"
  },
  "errors": [],
  "quality": {
    "score": 0.95,
    "issues": []
  },
  "sessionStatus": "in_progress",
  "nextStep": "document_back",
  "isComplete": false
}

Try it

cURL 
curl -X POST https://api.cip.pk/api/v1/kyc-sessions/SESSION_ID/process-frame \
  -F "step=document_front" \
  -F "file=@/path/to/cnic-front.jpg"
POST /kyc-sessions/{session_id}/process-liveness Public

Process multiple liveness frames (blink + head turn sequence). Send 5-10 frames captured during the liveness challenge.

Request (multipart/form-data)

FieldTypeRequiredDescription
filesbinary[]Yes3-20 image frames (each max 5MB)

Response (200 OK)

JSON 
{
  "step": "liveness",
  "passed": true,
  "data": {
    "livenessScore": 0.99,
    "blinkDetected": true,
    "headTurnDetected": true
  },
  "errors": [],
  "quality": { "score": 0.97, "issues": [] },
  "sessionStatus": "in_progress",
  "nextStep": "document_in_hand",
  "isComplete": false
}

Try it

cURL 
curl -X POST https://api.cip.pk/api/v1/kyc-sessions/SESSION_ID/process-liveness \
  -F "files=@frame1.jpg" \
  -F "files=@frame2.jpg" \
  -F "files=@frame3.jpg" \
  -F "files=@frame4.jpg" \
  -F "files=@frame5.jpg"
POST /kyc-sessions/{session_id}/upload-document Public

Upload a document for a KYC session. Used for manual document uploads (as opposed to camera capture via process-frame).

Request (multipart/form-data)

FieldTypeRequiredDescription
document_typestringYesOne of: cnic, passport, driving_license, selfie
filebinaryYesImage or PDF (JPEG/PNG/PDF, max 10MB)

Response (200 OK)

JSON 
{
  "status": "success",
  "data": {
    "document_id": "doc-123-456",
    "document_type": "cnic",
    "ocr_data": { ... }
  }
}

Try it

cURL 
curl -X POST https://api.cip.pk/api/v1/kyc-sessions/SESSION_ID/upload-document \
  -F "document_type=cnic" \
  -F "file=@/path/to/cnic.jpg"
POST /kyc-sessions/{session_id}/complete-step Public

Advance the KYC session to the next step. Called after a step has been successfully processed.

Request Body

FieldTypeRequiredDescription
stepstringYesOne of: upload, verify, liveness, complete

Response (200 OK)

JSON 
{
  "status": "success",
  "data": {
    "session_id": "a1b2c3d4-...",
    "status": "in_progress",
    "current_step": "verify",
    "kyc_status": null,
    "risk_tier": null,
    "completed_at": null
  }
}

Try it

cURL 
curl -X POST https://api.cip.pk/api/v1/kyc-sessions/SESSION_ID/complete-step \
  -H "Content-Type: application/json" \
  -d '{"step": "upload"}'

Wallets

POST /wallets/register JWT Required

Register a wallet address for ongoing monitoring. CIP will periodically re-score and alert on risk changes.

Request Body

FieldTypeRequiredDescription
addressstringYesBlockchain wallet address
chainstringYesOne of: ethereum, bitcoin, bsc, polygon, tron
customer_idUUIDNoLink to a CIP customer
external_refstringNoYour internal reference
labelstringNoFriendly label (e.g., "User deposit address")

Try it

cURL 
curl -X POST https://api.cip.pk/api/v1/wallets/register \
  -H "Authorization: Bearer YOUR_JWT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "address": "0x742d35Cc6634C0532925a3b844Bc9e7595f2bD18",
    "chain": "ethereum",
    "label": "User deposit wallet"
  }'
POST /wallets/score JWT Required

Score a wallet address. Returns risk category, score, and contributing factors.

Request Body

FieldTypeRequiredDescription
addressstringYesBlockchain wallet address
chainstringYesOne of: ethereum, bitcoin, bsc, polygon, tron
depthstringNoAnalysis depth: shallow, standard, deep

Response (200 OK)

JSON 
{
  "address": "0x742d35Cc6634C0532925a3b844Bc9e7595f2bD18",
  "chain": "ethereum",
  "riskScore": 23,
  "riskCategory": "low",
  "factors": [
    { "name": "mixer_exposure", "score": 0, "detail": "No mixer interactions detected" },
    { "name": "sanctions_exposure", "score": 0, "detail": "No OFAC/sanctioned entity links" }
  ],
  "scoredAt": "2026-03-31T15:10:00Z"
}

Try it

cURL 
curl -X POST https://api.cip.pk/api/v1/wallets/score \
  -H "Authorization: Bearer YOUR_JWT_TOKEN" \

    "address": "0x742d35Cc6634C0532925a3b844Bc9e7595f2bD18",

Screening

POST /screening/check JWT Required

Real-time name screening against sanctions lists (UN, OFAC, EU, NACTA, PEP). Returns matches above the configured threshold with fuzzy matching scores.

Request Body

FieldTypeRequiredDescription
namestringYesName to screen
dobstringNoDate of birth (YYYY-MM-DD) for disambiguation
id_numberstringNoNational ID / passport number

Response (200 OK)

JSON 
{
  "id": "scr-abc123",
  "screenedEntityName": "Ahmed Khan",
  "matches": [
    {
      "watchlistEntryId": "un-1234",
      "score": 0.45
    }
  ],
  "overallStatus": "clear",
  "createdAt": "2026-03-31T15:12:00Z"
}

Try it

cURL 
curl -X POST https://api.cip.pk/api/v1/screening/check \
  -H "Authorization: Bearer YOUR_JWT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Ahmed Khan",
    "dob": "1995-03-15"
  }'

Update the webhook URL for your tenant. CIP sends event notifications to this URL.

Response (200 OK)

  -H "Authorization: Bearer YOUR_JWT_TOKEN" \

  -d '{"webhook_url": "https://yourapp.com/webhooks/cip"}'

Error Codes

All error responses follow this format:

JSON 
{
  "detail": "Human-readable error message"
}
HTTP CodeMeaningCommon Causes
400Bad RequestInvalid JSON, missing required fields, file too large, unsupported file type
401UnauthorizedMissing or invalid Authorization header, expired JWT
403ForbiddenPlatform admin accessing tenant endpoint, insufficient role permissions
404Not FoundSession/customer/wallet not found, or belongs to different tenant
409ConflictSession already completed, duplicate external_ref
422Validation ErrorPydantic validation failure on request body
429Too Many RequestsRate limit exceeded. Retry with exponential backoff.
500Internal Server ErrorServer-side error. Contact CIP support.

Rate Limits

Default rate limits: 100 requests/minute for session creation, 300 requests/minute for status checks, 60 requests/minute for frame processing. Contact CIP support for higher limits.
